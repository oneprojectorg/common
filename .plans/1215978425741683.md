# Map pin hover state with hovercard

## Problem

Proposal map pins on the browse view (`ProposalsMapView`) already have an
active-state visual when hovered, but the design (Figma "Decision-Making"
node 17329-24620) calls for an accompanying hovercard above the pin showing
the proposal title, author, and council district, with click-through to
the proposal detail. The interaction needs to survive cursor transit from
pin to card, stay glued to the pin on pan, hide on zoom, and flip to below
the pin when the pin is near the top edge of the map.

## Approach

- Extend `@op/ui/MapMarker` with optional `hoverContent?: ReactNode`.
  When set, the marker renders the content inside an absolutely
  positioned overlay above/below the pin and manages its own
  open/close state.
- Use `react-map-gl/maplibre` `useMap()` to subscribe to the parent
  map's `zoomstart` event for "hides on zoom"; the natural DOM nesting
  inside `Marker` covers "glued on pan" for free.
- Cursor-transit: a small dismiss delay (~120ms) clears on mouseenter
  of the card so the user can move from pin to card. Mouseleave of
  either restarts the timer.
- Edge flip: a pure `getMapPinHovercardPlacement` helper compares the
  pin's pixel position (`map.project(lngLat)`) against the map
  container height + a min top buffer for the card itself and returns
  `'top' | 'bottom'`.
- A new `ProposalMapHovercard` in `apps/app/src/components/decisions/`
  composes the proposal-specific UI: title (font-serif title size),
  author (Avatar + name), council-district chip (the proposal's
  `category` — auto-tagged by `decision_boundaries`). The whole card
  is a `Link` to the proposal detail, falling back to `onClick` for
  parity with marker click.
- In `ProposalsMapCanvas`, add a `renderHovercard?: (id) => ReactNode`
  prop so the canvas stays presentational; `ProposalsMapView` supplies
  it with the per-proposal hovercard on desktop only (mobile keeps the
  tap-to-open behavior, no hover).

## Edge cases

- Anonymous proposals: omit author / link to profile (mirrors
  `ProposalCardAuthor`'s anonymous handling).
- Proposals with no category: omit the council-district row.
- Untitled proposals: fall back to the proposal's profile name (same
  fallback ladder as `ProposalCardTitle`).
- The map container being small (< 2 × card height): default to `top`
  even if it would overflow — the design always prefers above.
- Card click vs pin click: clicking the card navigates via `Link`; pin
  click still fires `onMarkerClick`. The card hover wrapper stops
  pointer-events from bubbling to the underlying Marker so the wrong
  one doesn't fire.

## Out of scope

- Mobile hovercard (no hover on touch; tap still opens the proposal).
- Touch-and-hold behavior on pins.
- Pinned/sticky hovercards.
- Animation polish beyond what the existing `Popover` uses (we use a
  simple opacity fade).
- Any change to the marker's active-state styling — Figma shows the
  card paired with the existing coral active pin, which we already
  produce.
